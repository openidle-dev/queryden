QueryDen does not run an inference server. When you use the AI features, the call goes directly from your machine to the provider you configured, with the API key you provided.

## Configuring a provider

Open **Settings → AI Assistant**, turn it on, and pick a provider:

- **OpenAI** — paste an `sk-...` key.
- **Anthropic** — paste an `sk-ant-...` key.
- **Google (Gemini)** — paste an `AIza...` key.
- **Local** — Ollama (`http://localhost:11434` by default) or any OpenAI-compatible server such as LM Studio (`http://localhost:1234`). No key needed.

The key is sealed with AES-256-GCM, using the same machine-locked key as the credential vault — never stored in plain text. Requests to the provider are made by QueryDen's backend, so the key never passes through the web view; it leaves your machine only in the request to the provider.

## Where the AI is actually used

- **EXPLAIN visualizer** — given a plan tree, the AI is asked for a one-paragraph diagnosis and a suggested `CREATE INDEX` or `ALTER TABLE` statement. The suggestion is read-only until you click **Apply**.
- **AI Assistant dialog** — the toolbar **Sparkles** (✨) button opens a dialog where you describe a query in natural language. The dialog sends your prompt (plus any currently-edited query for context) to the configured provider and replaces the editor content with the generated SQL.

## Model selection

The model list comes from the provider itself: once a key (or a local endpoint) is entered, **Settings → AI** asks the provider which models your key can use and lists them — new models appear without a QueryDen update. Press **Refresh** after enabling a new model on your account. If the list can't be loaded (offline, restricted key), type a model id by hand.

## Privacy posture

- No telemetry. The app does not record AI usage or send it anywhere except the provider.
- No prompts are stored unless **you** save the resulting suggestion to local history.
- No background pings. If you don't use the AI surface, no AI requests are made.
