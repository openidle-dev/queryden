PostgreSQL is QueryDen's first-class engine. The driver is the upstream `tauri-plugin-sql` with a local patch that adds support for several types upstream doesn't emit cleanly: `INTERVAL`, `OID`, multidimensional arrays, and a few `bytea` edge cases.

The patch also gives every editor tab its own session, so `BEGIN`/`COMMIT`, `SET`, temporary tables and prepared statements carry over between runs in that tab, and values come back exactly as `psql` prints them — `numeric` with every digit, `interval`, `money`, `regclass`, arrays, `infinity`, `timestamptz` in your local time zone. See [Statement-aware run](/docs/editor/statement-aware-run#each-tab-is-its-own-session).

## Connection

The standard PG connection fields apply:

- **Host** — e.g. `db.acme.dev`
- **Port** — default `5432`
- **Database** — the database name
- **User / Password** — stored in the encrypted vault
- **TLS** — used automatically whenever the server offers it, as on Supabase, Cloud SQL and RDS.
- **SSH tunnel** — optional. Real `ssh2`-backed tunneling; no `ssh` subprocess. Password or private-key authentication (`~/` paths work).

## Cockroach + Supabase

Neither is a separate backend in QueryDen — both speak the PostgreSQL wire protocol and connect through the same driver as Postgres.

- **CockroachDB** — supported through the PostgreSQL wire protocol. Pick **CockroachDB** in the connection dialog (it uses the PostgreSQL driver underneath, with CockroachDB's default port 26257); CockroachDB-specific behaviours (e.g. its dialect quirks) are handled by the server, not by a separate client driver.
- **Supabase** — PostgreSQL plus a connection-string helper UI for Supabase's hosted format. The helper generates the right host/port/SSL fields from a Supabase project URL; the driver underneath is the PostgreSQL one.
