There is nothing to set up. The first time QueryDen saves a connection it creates its encryption key, and from then on everything sensitive is written encrypted and locked to this computer.

## What's protected

Every secret QueryDen keeps — connection passwords, SSH passwords and key passphrases, credential profiles, your AI provider key — plus your saved queries, query history and local history is encrypted with **AES-256-GCM** before it touches disk. Nothing sensitive is ever written in plain text.

The data lives in QueryDen's app data folder: `~/.local/share/com.queryden.app/` on Linux, `~/Library/Application Support/com.queryden.app/` on macOS and `%APPDATA%\com.queryden.app\` on Windows.

## How the key is made

1. On first use QueryDen generates a random 256-bit key, stored in your user profile with owner-only access.
2. It reads this machine's hardware identity, so the key only works on this computer.
3. Both, plus a random per-vault salt, go through **Argon2id** — a memory-hard key-derivation function — to produce the encryption key.

Every write is atomic (temporary file, flush, rename), so a crash or power loss mid-save can't leave a half-written file.

<Callout type="info" title="Machine-locked by design">
Copy the folder to another computer — a backup, a synced drive — and it won't decrypt there, even with everything else intact. On your own machine the vault is protected by your OS account, so keep full-disk encryption and a screen lock turned on. An optional master password and OS-keychain storage are on the [roadmap](/roadmap).
</Callout>

## Credential profiles

**Settings → Credential Vault** holds named username/password pairs. Pick a profile in a connection instead of typing the password there, and changing the profile updates every connection that uses it.

## Moving to a new machine

By design the files don't decrypt on another computer, even if you copy the whole folder. To move your connections:

1. **Export** them with the **Import / Export Connections** button in the Database Explorer toolbar. You choose whether to include passwords; the export is a plain JSON file, so treat one with passwords like a password.
2. **Import** the file on the new machine. QueryDen re-encrypts everything with that machine's key.

If a file fails to decrypt (for example after copying the folder between machines), QueryDen shows a banner and refuses to save over it, so nothing on disk is lost while you sort it out.

Full details: [Vault internals](/docs/security/vault-internals).
