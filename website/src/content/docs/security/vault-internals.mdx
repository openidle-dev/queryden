The encrypted vault is what makes QueryDen safe to trust with production credentials. This page walks the layers; for the overview, see [the Security page](/security#vault).

## Each encrypted value

Every secret is sealed individually with **AES-256-GCM** and stored as base64 of:

| Part | Size | Purpose |
|------|------|---------|
| Nonce | 12 B | Random, freshly generated for every write |
| Ciphertext | variable | The encrypted value |
| Tag | 16 B | GCM authentication tag — any modification makes decryption fail |

Saved queries, query history and local history are sealed the same way as whole documents.

## The key

1. On first use QueryDen generates a **random 256-bit key** from the operating system's secure random source and keeps it in your user profile with owner-only access.
2. It reads the **machine identity**:
   - Linux: `/etc/machine-id`
   - macOS: `IOPlatformUUID`
   - Windows: the system UUID (`Win32_ComputerSystemProduct`)
3. A **random 16-byte salt** is generated per vault ([#14](https://github.com/openidle-dev/queryden/issues/14)).
4. All three go through **Argon2id** (19 MiB memory, 2 passes — the OWASP-recommended baseline) to derive the AES-256-GCM key. The derived key is cached in memory for the session so the slow derivation runs once.

If any input differs on read — another machine, another install — the authentication tag doesn't verify and the data refuses to decrypt.

## Writes are crash-safe

Every file is written to a temporary file, flushed to disk and renamed over the original, so a crash or power loss leaves either the old file or the new one — never a torn mix. If a file can't be decrypted, QueryDen tells you and refuses to save over it, so a failed read never turns into lost data.

## Roadmap

- An optional **master password** mixed into the key derivation.
- Storing the per-install key in the **OS keychain** (macOS Keychain, Windows Credential Manager, Secret Service on Linux).

## What we don't defend against

- A rooted / compromised OS. If an attacker controls your kernel, no userland app survives.
- Malware running as your own user account while you're logged in.
- A network attacker between you and a database that lacks TLS. Use SSL or the SSH tunnel — that's why they're there.
- You pasting a connection string in Slack. We can't fix that.

## Verify everything

QueryDen is open source, and the CI pipeline that builds the binaries runs in the same public repository. There is no closed-source layer.
